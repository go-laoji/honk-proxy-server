# 历史观测与诊断

T18 使用同一套 Rust API/CLI 和共享 React/Tailwind 页面交付历史观测、脱敏诊断、状态告警及受限任务控制。所有功能直接访问，不引入帐号或权限体系。

## 真实计数与时间窗口

`hps observe --window-secs 300`、`GET /api/v1/observability?window_secs=300` 与概览/连接/规则页共用同一套数据。查询窗口为 60–3600 秒。服务确认启动后每 5 秒采样，最多 721 点，保留一小时；读取页面不创造业务命中，页面隐藏时暂停轮询。墙钟向前或向后跳变会标记，速率/保留期使用单调时钟，重启会产生新的运行期并重置这些观察历史。

上传/下载速率按相邻累计字节与实际采样间隔计算，首点是基线。间隔内漏采时不补造数据，图表横轴按实际单调间隔排列。失败与路由拒绝分别计数，图中合并显示时明确标注。延迟数据使用独立的真实健康探测历史，见 [健康检测](health-usage.md)；它持久化且有明确预算，不等于业务请求延迟。

## 连接关联与规则命中

已结束连接只按源 IP、入口、目标主机/端口聚合连接数、失败数和业务字节。聚合精度 60 秒、保留一小时，查询边界可含部分分钟；每分钟最多 128 个分组，最多 61 个桶，页面/响应最多显示 200 组。容量不足或原连接观察容量超限时，`unrepresented_closed_flows` 明确计数；`total_groups`/`groups_truncated` 说明响应截断。这里不存请求路径、消息内容或 TLS 明文，也不把有限元数据聚合称为完整审计。精确逐连接的现有活动/最近记录仍有自己的 10000 / 512 条容量与生命周期。

业务规则命中在实际业务准入时累加，包含显式拒绝；模拟和健康探测不增加它。按配置版本与规则 ID 分开，未匹配项属于默认动作；从 `rule_hits.since_unix_ms` 统计至响应观察时间，独立于图表选择的短窗口。最多 16384 个计数器，超限命中会进入 `untracked_hits`，不会无界分配。计数器不因最近连接记录淘汰而消失，热更新沿用同一业务观察事实源。

DNS 名称映射仅来自本机未过期查询应答，逐项显示上游、观察年龄与剩余 TTL，最多 64 项并报告截断。未知/外部加密 DNS 不伪造名称或 ECH 识别；清理缓存后相应映射不再返回。


## 脱敏诊断与只读任务控制

日志页创建诊断任务，URL 保留请求幂等键及 epoch；接受后以任务 ID 恢复，离开页面不终止后台工作。预览后导出格式版本 1 JSON。Web 使用文件下载，Desktop 通过原生保存对话框写文件，并在 fetch、对话框返回和写入前检查当前连接/文档上下文。

`hps diagnostic start --window-secs 300 --request-id case-1 --wait` 可直接输出诊断 JSON；不等待时返回任务 ID。`hps diagnostic show <id>`、`controls <id>` 用于回查；也可用既有 `hps task show/wait/list` 按请求 ID 恢复。导出仅允许版本/Web build ID、平台、配置修订号、观察 epoch、资源/字节/错误计数、最多 100 条实际健康记录的分类计数和捕获就绪事实。收集有 30 秒期限及 64 KiB 结果上限，不包含实例名称、节点/业务地址、URL、磁盘路径、凭据或正文；不是一致性数据库备份。计数属于当前运行期，历史窗口属于有界采样，两者分别标明。

`GET /api/v1/tasks/{id}/controls` 声明当前可取消/重试能力与原因；控制使用 `expected_epoch + expected_version`。取消仅支持本实例保留的只读 `diagnostic_export`，持久终态为 `discarded/cancelled/diagnostic_cancelled`；完成与取消并发时仅一个终态胜出。配置发布、供应商提取及其他不可取消工作不会伪造回滚。CLI 的 `diagnostic cancel/retry` 必须传两个期望值；重试另给新请求 ID，产生新任务并关联源任务，原请求重复提交仍幂等。重试输入最多保留 128 项、完成后 600 秒，重启、过期或配置来源变化后拒绝重放。持久任务结果遵守已有任务保留期；后台结果落库失败会显式报告，不等于收集成功。

## 状态变化告警

`GET /api/v1/observability/alerts`、日志页及 `hps diagnostic alerts` 共用一份真实状态变化流。服务确认启动后每 5 秒采样：已运行且需要代理的入口没有全局可准入节点；已启用供应商实际提取失败/结果不确定；已配置 Linux 透明/DNS 捕获未就绪；约一分钟内实际业务失败率超过阈值。失败率分母为关闭成功 + 失败，排除策略拒绝和主动断开，达到最少完成连接数才判异常。全局有节点不代表每条特定规则一定可用，通知不替代逐请求路由解释。

`[alerts]` 默认启用各条件，`cooldown_secs=60`（5–3600）、`failure_min_count=20`（1–100000）、`failure_percent=50`（1–100）。控制台先保存候选并审阅，再显式应用；并发配置变化返回冲突。可全部关闭或逐条关闭。初次异常立即产生，条件保持不重复通知；恢复和后续变化使用每条件单调时钟冷却，报告合并变化数。未知状态/请求进行中不伪造恢复，供应商事实只采用同来源配置指纹；通知不重放购买、不修改网络，也不向外部服务发送消息。

通知仅在当前 Daemon epoch 内存保留最近 128 条，无账号未读/确认状态。无 `after` 返回最近的 `limit` 条；带 `after` 按顺序返回其后最早的 `limit` 条（1–100），客户端按最后返回的 sequence 继续，不能跳到 head 而遗漏中间通知。`truncated` 表示保留缺口或游标超前；重启后用新 epoch 重建基线。Desktop 系统通知由 T20 作为同一事实源的本地适配器提供，不建立第二套告警判断。
