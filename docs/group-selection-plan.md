# T10 节点分组与统一选择实施计划

对应 [Issue #15](https://github.com/go-laoji/honk-proxy-server/issues/15)，覆盖 GROUP-01–05。接入现有 Rust Dialer、短效动态池和 HealthRegistry，不另建健康事实源，无项目账号或入口访问控制。

## 配置与语义

选择配置位于 `proxy.selection`：分组列表、默认组、按入口绑定、节点/来源标签和有界会话表。未配置组保持现有全池轮询兼容行为。分组成员为明确节点或来源的并集，标签和代理协议为进一步过滤条件；`include_all` 必须明确开启，空组如实拒绝新连接。静态节点、来源和入口引用在整份配置校验，动态 lease ID 可留作已过期/缺失引用解释。

提供 fixed、failover、latency、round_robin、weighted。Failover 从已合格成员中按明确顺序选择，不重放已经交给节点的业务请求；实际握手失败只影响后续选择。Latency 只使用当前健康策略的新鲜主动探测延迟，没有证据不杜撰评分。加权轮询按有界整数权重分配。手动 pin 优先且严格限定：pin 不可用时只允许 `fallback_nodes` 中且仍属于组的节点；不自动扩大到全池或直连。

会话键支持源 IP、源 IP+目的地址，并始终隔离入口/组/策略。TTL 不超过配置值、节点剩余可准入寿命及单调截止时间；重用前重新检查健康、启停、来源指纹及协议能力。没有源地址的诊断请求不建立真实会话。已有连接继续持有原 socket，不承诺迁移或租约到期后保活。当前所有代理均 TCP-only，UDP 诊断必须明确排除，不能继承 TCP 健康。

## 提交切片

1. 配置、引用校验及解释 DTO；统一候选/选择器与资源边界，覆盖固定、回退、租约、标签、权重、健康延迟和会话约束。
2. HTTP/HTTPS/SOCKS5 入口传递真实来源/入口上下文，选择器与拨号路径共用；配置代际沿用现有准备/激活流程，旧连接不迁移。
3. API/CLI：分组 CRUD、pin/unpin、候选分页与只读模拟。所有配置写入使用 expected_revision，并通过同一激活路径；诊断不推进轮询、不污染会话或补池需求。
4. 共用 React/Tailwind groups MPA、组成员/候选与策略解释、引用/空组提示、编辑/删除/固定和版本冲突；Desktop 只增加同一 API 的原生桥契约。
5. 实际多个代理出口与入口矩阵、短效租约/健康变更及资源测试、macOS/Linux、浏览器与可用时实际 Desktop 验收，文档与 Issue 回报。

嵌套组和高级 Score 留给 T19；目标规则的组选路由 T11 使用同一选择器，完整 Linux 透明流量由 T15 接入。不能用默认全池可用数量掩盖默认组或绑定入口无可用成员。
