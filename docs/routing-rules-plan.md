# T11 规则路由实施计划

对应 [Issue #16](https://github.com/go-laoji/honk-proxy-server/issues/16)，覆盖 RULE-01–06。复用已实际验收的显式代理、DNS 与分组选点；T09/T10 的独立桌面窗口待 Mac 解锁，不阻塞规则核心开发。只做流量路由，无项目账号、角色、入口认证或功能权限。

## 语义

规则放在 `proxy.routing`，按数组顺序首条命中。一个规则内的域名/后缀、目的 CIDR、端口范围、传输、入口协议、入口 ID、来源 CIDR和本机进程条件组合为 AND，各列表内部为 OR。支持启停、CRUD 和明确排序；无匹配时使用配置的默认动作，初始默认继续现有入口/默认组选择。

动作包括指定节点、指定组、明确直连和拒绝。节点/组仍经统一健康和租约准入，指定节点不会改成其他节点；拒绝与明确直连不触发供应商补池。明确直连复用共享 DNS，HTTP 目标 Host 与 CONNECT 端到端字节保持不变，不因其他动作失败而自动直连或重放业务。

显式代理直接提供的目标域名优先。CIDR 匹配字面目标 IP，不为模拟额外解析域名。IP 对应的 DNS 观测属于推断，默认不用于域名匹配；用户明确开启后，也只接受当前未过期的单个候选，多个候选或不可见域名保持未知。外部加密 DNS/ECH 不解密。

本机进程匹配只能使用实际 Linux 数据面提供的来源，不能把 Daemon 进程当客户端，也不能宣称识别远端 HTTP/SOCKS 客户端或网关后的进程。尚无已挂载、验证过的进程来源时，启用此条件必须拒绝发布并解释不支持原因；disabled 规则可以保存供后续配置。Linux 进程及用户态/内核版本一致性的最终证据与 T15 数据面联合验收，未完成前不关闭 T11。

## 提交切片

1. 规则配置、引用/数量/组合校验、不可变编译器和匹配/解释 DTO；未知上下文有明确不匹配原因。
2. 自有 Dialer 与三个实际入口使用同一匹配器、统一节点/组选点和明确 direct/reject；连接保留决策与配置代际供 T13 观测。
3. 规则候选和激活分离：CRUD/启停/排序生成未激活的配置候选，可指定候选作为下一次编辑基准；显式 apply 使用已有配置激活/CAS/失败保留机制，禁止保存成功冒充运行生效。模拟可选择运行或候选版本，显示版本、时间与健康候选来源。
4. 统一 API/CLI 与共用 React/Tailwind rules MPA，支持排序按钮/键盘、候选/运行状态、引用错误与冲突、模拟上下文和结果。Desktop 仅增加相同 API 桥，无分叉业务逻辑。
5. 实际 HTTP/HTTPS/SOCKS5 与多出口的首条命中/动作/字节验证，DNS歧义、未知进程、失效节点、保存未激活/失败/CAS 等故障回归；Linux 的实际进程来源和内核代际切换另有真实内核证据。

规则默认上限 1024，所有条件列表、CIDR/端口/名称、模拟轨迹和 API 体积有界。候选诊断不推进轮询、写会话或产生网络/采购副作用。新路由决策用于新接入连接，旧连接不承诺迁移；候选界面说明运行健康/租约是实时事实，不伪装成历史配置快照。

## 后续 Linux 联调约束

实际入口的手动启停覆盖在 enabled 未变化时跨热更新保留，修改 enabled 或重启才清除。按需补池按供应商、策略和实际入口隔离；T15 的透明入口必须传入独立稳定入口 ID，并把实际活动的透明入口纳入来源需求聚合，不能沿用显式入口的需求或仅打开端口就触发购买。
