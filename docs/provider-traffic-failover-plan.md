# 代理租约在业务失败时的补池计划

对应 [Issue #51](https://github.com/go-laoji/honk-proxy-server/issues/51)。

1. 业务拨号识别代理端点、认证、隧道握手和明确的快代理转发错误。失败租约立即停止新准入，由后台任务按租约 ID、来源和配置指纹持久撤销，已建立的连接自然结束。存量手动节点和订阅节点保持原有行为。
2. 撤销后立即唤醒原补池控制器，继续使用水位、最小间隔、日预算、在途任务和健康准入。不在客户端请求中直接调用供应商 API。仅在原路由下选其他可用端点，空池时有界等待一次补池，最多重试一次。
3. 隧道建立前可重试；明文 HTTP 发送后仅重试无请求体的 GET / HEAD。普通目标站状态透传，不在隧道建立或响应发出后重放内容。
4. 使用独立 SQLite 和回环地址模拟快代理 `getdps`，验证请求格式、旧 IP 入池、代理失败后撤销、供应商返回新 IP、同一客户端请求成功；覆盖目标站错误、不能重放的请求和预算不足。测试不调用真实订单接口，不修改宿主网络配置。
