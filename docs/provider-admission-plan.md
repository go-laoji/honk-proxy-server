# 供应商租约准入与业务故障

对应 [Issue #53](https://github.com/go-laoji/honk-proxy-server/issues/53)，沿用 #51 的租约淘汰与补池机制。

1. 有效的供应商租约发布后即可参与选点。健康探测继续报告连通性、鉴权和延迟，供应商库存与补池按已发布租约的期限、来源状态和实际连接失败计算。
2. 租约在业务建立代理连接失败后由后台撤销，并按原预算与限频补池。旧配置中的探测自动淘汰字段继续可读取，控制台移除该选项。已发送的业务数据沿用原有重试边界。
3. 用回环快代理验证主动探测失败时节点仍可选，真实 CONNECT 遇到同样的鉴权失败后，旧租约被淘汰，替代租约让同一次客户端请求成功。确认库存、节点详情和健康检测页面对准入状态的报告一致。
