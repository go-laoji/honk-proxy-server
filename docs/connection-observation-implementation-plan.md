# T13 活跃连接与流量观测实施计划

Issue：[#18](https://github.com/go-laoji/honk-proxy-server/issues/18)，分支 `feature/connection-observation`，基于 T12 节点登记表。完成后回接 T12 的逐连接关联。没有项目账号或已认证操作人假设。

## 当前实际路径

HTTP 正向请求、CONNECT 与 SOCKS5 CONNECT 最终调用 `Dialer::connect_context/connect_routed`；代理出口在协商完成后由 T12 `NodeGuard` 包装业务 IO，Direct 当前不经过该门。HTTP 正向出口是每个请求一个关闭式上游交换，入站 HTTP keep-alive 可有多个业务交换；CONNECT/SOCKS 是一个隧道。TLS 代理层在包装业务 IO 之前完成，HTTPS 目标内容保持不透明。HTTP 请求与响应体通过 `limited` 流式处理，隧道通过双向 `relay`，均有取消与资源预算。

因此“业务连接/交换”与“已接受入口 TCP 套接字”必须分别显示，不能强行使两者相等。探测与固定 DNS 诊断通过 ProbePlan，不混入业务连接、业务流量或需求购买。

## 分批提交

1. **同一核心事实源**：扩展 NodeRegistry，保留 CAS 操作门与节点计数，在相同生命周期内登记业务连接 ID、进程实例 epoch、单调时间、入口/来源/目标、规则/配置代际、组/节点/来源、选点摘要与 Direct。保留有限的最近终态，固定容量，观测容量不足显式计数；列表不冒充完整无限历史。拨号失败、规则拒绝和未找到出口使用固定错误分类，不存储请求路径、首部或正文。
2. **实际字节与主动断开**：包装协商后的业务 IO，按实际成功 read/write 的字节数累加，正确处理部分写入、vectored IO、半关闭、异常和取消；不把待写缓冲长度算成已写出。统计边界是 hps 的出口业务流读写：HTTP 包括转发 HTTP 首部，隧道包括目标 TLS 密文；不声称对端最终收到了全部字节。上游握手及 HTTPS 代理 TLS 握手不计入。流量总计从本进程启动起算，使用单调累计时间差采样速率，标明单位和区间。
3. **有界快照与写范围**：服务端冻结有界列表，TTL、实例 epoch、筛选指纹与分页明确。快照到期/实例变化重新获取，不能误把旧实例 ID 用于新实例。单个断开携带实例与连接 ID；批量先预览具体 ID 和数量，再确认所见预览，确认不会重新匹配并扩大到后来出现的连接。结果区分已请求取消、已经结束和未包含的记录。取消唤醒挂起的读写，连接实际退出后由 RAII 归零；不称为迁移或无感换节点。
4. **API/CLI 与共享 MPA**：connections 查询/详情/摘要/断开预览/确认接口、typed client、CLI `connection`、受限 Native 桥；React/Tailwind `connections.html` 提供筛选、暂停/刷新、明确确认、路由和错误详情。页面切换取消读取，重连重新取快照；T14 再接统一 SSE。节点详情链接到同一连接事实；仪表盘显示实际业务连接、速率/累计量以及可进入详情的出口、提取、激活或内核异常。
5. **验收与记录**：真实 HTTP/HTTPS/SOCKS 三入口与三上游、Direct、HTTP 流式体、端到端 TLS 密文、不重放、半关闭、部分读写计数、取消、入口停止与热引擎共用事实。旧 epoch/过期快照、预览后新连接不会被批量误断、容量与终态淘汰、客户端切页恢复。API/CLI/浏览器/独立桌面与 macOS/Linux 回归，分切片提交后回复 Issue。

## 语义与资源约束

- ID 在一个进程 epoch 内单调且不复用，热配置不重置；重启产生新 epoch。记录的是实际流量发生时的路由版本，不能使用当前配置重算并声称是历史事实。
- 域名只存实际目标和已使用的 DNS 上下文来源。显式代理不从远端请求头推断本机 PID/程序；Linux 原始进程信息与内核版本由 T15 实际捕获后填入，当前为未知。源端口如尚未传递应明确为空，不能用 Daemon 端口代替。
- 逐连接记录不保存上游凭据、认证头、URL 查询、业务明文或 TLS 内容。IO 计数允许包含协议首部的字节数，但不保留其内容。
- 默认保留至多 10000 个完整活跃观测和 512 个最近终态，快照和断开预览各有个数、条目数和 TTL 上限。超出完整记录容量时业务继续受原资源准入约束，累计数与节点计数保持真实，响应必须显示未完整观测数量；批量断开只涵盖预览列出的具体 ID。
- 取消信号必须在持续挂起的 IO 中也生效，不能依赖下一次流量才结束。HTTP 正向响应体的退出与原生任务释放需要共同验证，不能只删除列表记录。
- 速率由前后两次实际累计快照与服务单调时间差计算；刚连接、实例重启或样本不足时显示采样中，不能伪造 0。长期历史和持久聚合由 T18 接续。
- 配置/供应商/内核错误沿用各自实际事实源与固定错误分类。没有真实内核就绪证据时继续显示未就绪，不能用观测页面或环境预检替代接管。

## 与后续任务的契约

T14 使用相同 ID/epoch 与终态，统一任务、事件和游标；并补齐现有配置预检取消后的工作所有权，避免取消请求提前释放操作锁而阻塞工作仍在运行。T15 在同一拨号/登记表注入透明流的稳定入口 ID、原始目标、进程来源及内核规则代际，复用节点门、统计、取消和补池需求范围。
