# 代理节点 IP 归属地

对应 [Issue #47](https://github.com/go-laoji/honk-proxy-server/issues/47)。

## 节点库存与控制台

- 在服务端使用固定提交的 `lionsoul2014/ip2region` Rust 查询库。节点优先使用已有、仍有效的健康探测出口 IP。没有出口 IP 时，可对配置为公网 IP 的节点端点做离线查询。结果标注出口或端点来源，供应商提供的地区字段继续单独保留。
- 节点列表和详情显示国家、省、市及可用的运营商信息，现有搜索框支持地区关键字并在分页前匹配。无数据库、无可用公网 IP、无匹配记录时允许正常列出节点。
- 浏览器和 Desktop 经同一服务接口显示数据库版本，手动检查并更新当前连接服务的数据库。更新后重新查询节点。已有健康记录直接用当前数据库解析。

## 数据获取与切换

- 从上游 GitHub `master` 的 `data` 目录获取两个 XDB 的 Git blob SHA 和大小。固定来源、下载超时及体积上限，校验下载内容和 XDB 版本。两份数据库均通过验证后才发布新快照。
- Daemon 和 Desktop 内置的本地服务使用各自服务数据目录。更新在后台请求内进行，更新请求互斥，查询继续读取当前版本。持久版本通过原子替换清单一起生效，失败时保留原版本。
- CI 原生包、独立 headless 构建和 Tauri 默认打包钩子获取上游快照。正式 Desktop 打包复用同次构建中 Daemon 的数据版本。源码编译和测试支持无数据库离线执行。

## 验收

- 对 IPv4、IPv6、地区搜索和缺失值验证节点响应，检查更新失败、并发、重启读回及默认打包数据。使用合成数据库或上游公开样例，不发送节点 IP 到外部服务。
- 验证 Rust API、Desktop 传输、页面交互和实际原生构建。开发进程启用 `HPS_FORBID_HOST_NETWORK_CHANGES=1`，验证使用隔离状态目录及回环管理端口。
