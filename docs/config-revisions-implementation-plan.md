# T05 配置版本实施计划

对应 [Issue #10](https://github.com/go-laoji/honk-proxy-server/issues/10)。使用全 Rust 单写者 SQLite，独立 CLI/Daemon 与共享 MPA，无账号、身份或角色表。

## 提交切片

1. `crates/storage`：有界请求队列和独立写线程，SQLite WAL/外键/迁移；数据目录/实例锁；不可变版本、共享草稿、期望版本及激活历史。重启恢复期望配置，分页读取摘要，错误不带配置正文。
2. `crates/application` 配置协调：校验与凭据占位符合并；候选引擎及监听预准备；发布失败不替换当前版本。相同监听复用句柄并停止旧代际接入，已有连接保持原配置排空。启动管理监听和日志字段变化进入明确 pending_restart，不伪报实际已应用。
3. API/CLI：共享草稿、离线/在线校验、版本、脱敏差异/导出、激活和回滚，所有写入携带期望版本；数据目录由本机启动参数配置，远端 API 如实展示实际位置。
4. React/Tailwind MPA：共享配置工作台、验证错误、版本冲突、差异、当前/期望/运行版本、激活/回滚和导入导出，两种 transport 共用页面。
5. 验收：重启恢复、并发编辑冲突、配置/绑定/TLS 失败保留旧代际、凭据脱敏与占位符恢复、需重启字段、真实代理连接跨激活持续、CLI/API/浏览器/Desktop。

## SQLite 模型与一致性

- `schema_migrations` 记录向前迁移版本，未知较新版本拒绝打开，避免旧程序误写。
- `config_revisions` 用整数自增主键、父版本外键、配置 JSON、内容校验和、创建时间和说明记录不可变版本。
- `config_head` 单例以外键指向期望版本，按 expected_revision 比较并更新。
- `config_draft` 单例共享草稿，以独立 draft_version 和 base_revision 检测多页面并发，不设账号所有者。
- `config_activations` 记录目标版本、前一版本、状态、时间和脱敏错误码；运行状态由当前进程实际引擎决定，数据库旧 applied 记录不证明新进程就绪。
- SQLite 连接只由一个线程持有；异步网络任务通过有界队列/oneshot 调用，不在热路径阻塞。启停/激活另由应用层单写锁串行化。
- 配置导出默认脱敏；`[REDACTED]` 只可引用同 ID 已有凭据，新节点引用缺失占位符拒绝。数据库目录与文件使用操作系统权限，应用接口不增加用户认证。

候选监听和 TLS 准备在修改期望指针前完成。提交指针与内存切换之间若进程退出，重启重新按期望版本准备，未实际启动不报告 ready。需要重启的字段只更新期望版本，运行版本保持旧值，回滚同样验证期望版本及实际结果。

写事务使用 IMMEDIATE，在读取比较版本之前取得写锁，避免 SQLite WAL 的读事务升级绕过 busy_timeout。默认保留最近 200 个配置版本，并额外保护期望/运行版本、最后实际应用版本、草稿基线及仍有连接的流量代际。清理旧记录时截断已被清理的父版本引用，保留版本的配置正文与校验和不变；激活历史也有界。活动与任务天数策略随对应模块启用。
