# T12 节点管理实施计划

Issue：[#17](https://github.com/go-laoji/honk-proxy-server/issues/17)，分支 `feature/node-management`。

## 已有事实与边界

静态节点来自版本化 `proxy.upstreams`；供应商节点来自 SQLite 的独立租约 `lease:<id>`，归属一个来源指纹和批次。`refresh_pool` 只发布仍有效且来源匹配的租约，并按端点去重、寿命和水位截取。健康证据按端点身份和检测维度复用。列表必须同时显示库存记录和当前发布/准入状态，不能把数据库中的有效租约数量当作可调度节点数量。

节点管理不增加项目账号、登录、权限或入口认证。供应商凭据继续用于上游协议，但列表、预览、详情、错误和日志不能回显密码。Linux 数据面由 T15 接续，所有业务拨号复用本计划的准入门和连接事实。

## 交付切片与提交

1. **持久操作状态与运行准入**：迁移 0007 保存节点的独立操作状态和单调版本；启用、禁用、排空、软删除用 CAS。共享节点登记表覆盖当前和退休引擎；禁用/排空/软删除后停止新的拨号，已有套接字自然排空。真实的逐节点在途拨号/连接计数由 RAII 管理，探测不混入业务连接。恢复启用不延长租约，不绕过配置禁用、健康或来源校验。静态与动态使用相同的可恢复操作门；静态配置的物理修改继续通过现有版本激活；动态删除只抑制所选租约 ID，不删除来源、批次或其他同端点租约。
2. **库存查询、详情与导入**：有界分页、名称/来源/组/协议/能力/状态/剩余寿命过滤和排序；静态与动态记录统一返回脱敏 DTO。分别呈现操作状态、租约状态、健康维度和实际准入原因。返回来源/批次/组/最近探测与真实连接关联。导入先解析、逐条校验及脱敏预览，再显式应用到配置版本；数量和字节有上限，不以部分成功冒充全部成功。预览不拨号、不触发购买。
3. **API 与 CLI**：统一 typed client；节点查询/详情/操作/导入接口。写操作携带所见运行配置版本与操作版本；操作状态不隐式修改配置，静态配置改动复用版本冲突、引用校验与激活事务。重复或过期操作明确返回冲突，软删除保留稳定引用并明确显示不可用；配置物理删除仍受规则引用校验。操作工作由服务拥有，客户端离开不释放尚在进行的写事务。
4. **共享 MPA**：`nodes.html` 真实列表与详情、导入预览、动作结果；筛选与分页写入 URL，可刷新恢复。来源页链接到相关节点/批次；仪表盘显示实际库存、可调度、近到期、过期及来源异常。桌面和浏览器使用同一页面、原生桥只扩展受限的 API 路径。关联连接的详细生命周期与主动断开在 T13 使用同一登记表扩展。
5. **验收与文档**：真实 HTTP/SOCKS 连接验证禁用即时阻止新拨号、旧连接排空和热配置后计数不丢；迁移/重启/CAS/租约批次隔离/删除引用/导入错误与脱敏回归；API、CLI、浏览器真实交互和移动布局；独立桌面窗口验收。按切片提交，完成证据回复 Issue 后关闭。

## 状态语义

- `enabled` 操作状态表示没有额外人工限制，仍必须满足配置启用、来源匹配、未到期、剩余寿命与健康要求。
- `disabled` 和 `draining` 都立即阻止新业务拨号；排空状态额外显示尚未释放的拨号/连接数，归零后仍保持排空，直到显式恢复。
- 动态 `deleted` 为可恢复的单租约抑制记录，不回滚付费提取，不删除批次，动作本身不直接调用提取 API。已显式启用的补池策略仍可按需求、预算和水位决定后续提取。后续供应商新批次是新租约，按独立寿命和身份处理。同端点去重优先保留未受人工限制的租约；操作完成后重算池，已有连接继续保留原租约身份。
- 静态和动态的列表删除均为可恢复的单节点抑制。静态配置的物理删除在配置版本工作区完成，组和规则引用校验失败时保留现有配置。这样一次操作只提交一个 CAS 事务，避免配置已激活、操作状态却冲突的部分结果。解除人工限制不会把配置中 enabled=false 的节点显示为可用。供应商租约自然过期、来源变更、快照撤销与人工操作是不同维度。
- 操作状态按稳定节点 ID 生效；修改静态 ID 表示新节点。操作表有容量和历史清理上限，活跃连接归零即移除计数项。

## 后续集成约束

T13 扩展当前真实连接登记表，不能另建互相矛盾的节点计数。T15 捕获流量在共享拨号层经过同一个操作门，并传递稳定入口 ID、配置代际、来源和进程上下文。当前平台未实现的 UDP 能力必须返回 unsupported；IPv4/IPv6 的实际可达性使用已有健康维度，不能从节点名称推断。
