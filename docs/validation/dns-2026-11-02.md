## 明确边界

完整业务 TCP/UDP 透明数据面仍由 T15 交付，Linux 完整 ready 保持 false；DNS 捕获单独报告实际状态。System 无 wire TTL；DoH 为 HTTP/1.1 POST；UDP DNS 不能通过 TCP-only 节点。显式代理业务域名继续交给所选上游远端解析。外部加密 DNS 与 ECH 不解密，不伪造上下文。捕获对象/cgroup/端口变更或关闭需要重启，旧 connected DNS socket 需重建。

## 实际 Desktop 窗口验收

2026-11-02 解锁期间，使用最终 T13 共用页面的 `HPS Connection Validation.app`（独立 bundle ID `dev.hps.connection-validation`）连接隔离的 `http://127.0.0.1:17999/`。窗口显示的 web_build_id 为 `169275ac5ccde608668c35ad9b695ced253ca58ed2a8c5093b87e18cd1468837`。

通过实际窗口完成 `localhost A` 查询，结果为 `NoError / 127.0.0.1 / 6 ms`；System 上游显示 TTL 未知并明确提示不缓存。点击清理缓存后，在 DNS 策略编辑器将 `cache_entries` 从 2048 改为 1024，保留其他设置，保存并激活为 r2；窗口结果与布局已检查。没有修改用户原有 `.app`、17900 endpoint 或 yun-free 配置。

T09 的窗口门槛由以上实际操作满足。后续其他页面验收时设备重新锁定，不影响已完成的 DNS 记录；其他模块不据此视为通过。
