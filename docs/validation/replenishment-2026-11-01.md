# T07 补池与预算验收

- 日期：2026-11-01（Asia/Shanghai）。对应 [Issue #12](https://github.com/go-laoji/honk-proxy-server/issues/12)。

## 交付与验证

来源 refill 配置、纯水位滞回策略、后台单来源控制、真实拨号需求信号、退休/预测窗口、数量参数映射和最大准入库存已实现。schema 5 增加 UTC 每日请求/节点账本、控制器暂停/退避与任务触发来源，迁移保留的已有提取记录。手动和自动请求统一原子预留，删除任务历史或重启不恢复预算。

新增纯策略测试验证空闲/维护模式、目标滞回、最大水位、在途合并、预算与退避。存储测试验证手动/自动共享预算、在途预留、历史删除不返还、旧 schema 账本回填、UTC 换日/回拨、未知结果暂停、确认恢复不清空预算/冷却，以及确认不能跨越在途或新任务。额外来源隔离回归确认租约分页不会混入其他来源历史。

**4 项实际 HTTP 控制器集成测试**验证：仅端口握手不触发补池，真正空池拨号触发；8 个并发评估与手动触发合并在途；按目标先请求 2 个再请求 1 个，HTTP 数量参数与预算一致；空闲后短租约到期不重复购买；损坏响应暂停不重放；429 遵守 Retry-After；连续空结果在失败上限停止。

浏览器完整 **9 项 E2E**通过。新流程在真实 Daemon 上保存维护策略，暂停已发送的首批请求，确认其完成但不继续购买，显式恢复后只补足 1 个节点；显示请求预算 2/2、节点预留 3/3，额外手动提取被 429 拦截且供应商没有收到第三个请求。移动布局截图已实际检查。

独立 CLI/Daemon 使用临时持久目录及实际 HTTP 提取服务验收：自动提取 2 个节点、暂停/恢复、正常退出后重启；库存仍为 2、使用量仍为 1 次请求/2 个节点、到期时间不变、供应商总请求仍为 1；超预算提取退出码为 5。进程不依赖图形会话，未向付费供应商发请求。

macOS aarch64 与官方 `rust:1.98.1-alpine` 实际 Linux aarch64 musl 完整套件各 **62 项 Rust 测试**通过。随后新增来源隔离测试在 macOS 与 Linux 定向验证，各累计 **63 项**，没有代码语义变更。Linux 使用只读隔离源码与独立缓存，没有特权或 eBPF。

fmt/clippy、TypeScript、Prettier、生产构建通过；Desktop 桥 allowlist 单测和 clippy 通过，新的 .app 已成功打包。T06 已验证实际 Desktop 来源/提取页面，本次新增控制路径通过桥测试与同一 React 页面的浏览器测试；未把本次打包等同于新的桌面窗口操作验收。
