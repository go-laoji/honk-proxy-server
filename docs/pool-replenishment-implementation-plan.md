# T07 水位、到期预测与预算补池实施计划

对应 [Issue #12](https://github.com/go-laoji/honk-proxy-server/issues/12)。沿用 T06 的单来源在途任务、持久批次租约和无重放抓取，不在代理请求中同步访问供应商。

## 提交切片

1. 在来源配置中增加 refill 策略：启用、按需/持续维护模式、最小/目标/最大可准入库存、批量、退休/预测窗口、空闲时限、每日请求/提取数量预算和退避。每日预算以 UTC 日期标注，手动和自动提取共用。配置和操作继续使用全 Rust API/CLI 与同一 React/Tailwind MPA，不增加账号或权限模型。
2. schema 5 增加独立每日使用账本与控制器状态，迁移已有请求。预算在受理事务中预留，在途及结果不确定均保守计数，不随完成任务历史裁剪丢失。时钟回拨不能回到较早预算周期。暂停、退避和滞回状态跨重启保留。
3. 每来源一个决策器，由服务级定时循环驱动。库存按来源/配置指纹和不同协议端点计算，地域由对应供应商过滤参数隔离。将即将退休的租约排除，并计算预测窗口后的库存。低于最小水位开始补至目标，受最大可准入库存、批量、在途和预算约束；不因填到最小水位就中途停止。
4. 默认按需模式只响应真实代理拨号需求，空闲后不继续购买；显式 maintain 模式才长期维护目标。实际请求只记录需求计数，后台控制器随后补充。未启用自动策略时保持 T06 手动行为。健康准入在 T08 接续，本阶段区分期限库存与健康通过。
5. 429 按明确拒绝与 Retry-After 退避；传输/响应丢失等 outcome_unknown 暂停，禁止自动重放。额度、鉴权、白名单或订单问题暂停直到配置修复并显式恢复；恢复不清空预算或绕过最小请求间隔。空响应等有界指数退避，连续失败可暂停。
6. 控制器 API/CLI/页面展示库存/预测/在途、预算/重置时间、下次允许时间、暂停原因和实际决策，支持暂停、确认恢复与单次评估。控制操作不修改供应商订单、白名单或购买套餐。

## 验收

纯决策测试覆盖低水位滞回、批量不足/最大水位、提前窗口和租约临界；实际 HTTP 服务验证并发触发合并、在途预留、响应不确定不重放、429/Retry-After、空结果/无配额、空闲停止和进程重启。账本测试验证手动/自动共享预算、跨日及回拨、历史清理后不重置。API/CLI/共享页面均须展示真实控制器状态，不使用演示库存或伪造健康。
