# T08 统一健康与真实流量反馈实施计划

对应 [Issue #13](https://github.com/go-laoji/honk-proxy-server/issues/13)。先完成 T04/T06/T07 的基础上，健康状态成为所有入口共用的事实源；仍无项目账号、认证或角色权限。

## 提交切片

1. 健康配置、DTO 和 Rust 实际探测器。默认启用 TCP IPv4 HTTPS 穿透探测，目标可配置；IPv6 独立配置和记录。UDP 尚无实现时明确 unsupported，不由 TCP 成功推断。探测按端点连接、上游 TLS、供应商认证、目标穿透/TLS、HTTP 响应分层，使用自己的 GET，不携带用户业务数据或 Cookie。
2. 持久健康状态、探测运行和单个/批量任务。节点身份绑定协议/端点/凭据和探测策略指纹；旧代际结果不能提升新凭据节点。支持任务进度、重启中断恢复、有界历史/队列、并发/次数预算、退避与生命周期检查。新批次快速准入；临近退休、过期和预算不足不反复探测。
3. 引擎共享健康注册表和有界真实反馈。HTTP、HTTPS、SOCKS5 选择同一健康状态，明确目标地址族。真实连接/认证失败与目标站点 403/429、本地不足分开；不重放业务请求，不全局判死目标拒绝。探测不计为用户需求，不让按需补池被自身探测唤起。
4. 应用协调检测、池发布和补池预留。未知/待检测节点先保留库存槽位，防止因为探测在途再次购买；只有满足相应能力和寿命条件才新准入。健康预算/本地探测目标不可用时不持续购买新批次来代替修复。旧连接继续运行，不声称迁移。
5. API/CLI/React Tailwind MPA 健康页面：策略、各维度状态、最近时间/耗时/阶段、任务/预算与单个批量触发。Desktop 复用同一页面和显式原生桥路径。全局任务/SSE 在 T14 统一，不以端口可达或一盏绿灯代替穿透证据。

## 配置和兼容性

默认探测目标为可配置的公开 HTTPS 页面；解析只用于自有探测目标，按所需 IPv4/IPv6 选定 IP，并保留正确 TLS 名称和 Host。探测目标证书正常验证，可显式信任自定义 CA。证书路径随 TOML/数据目录规则解析，不提供跳过验证。

旧显式代理/配置测试在各自场景显式停用健康，继续验证原有协议与配置边界；健康场景启用并使用本地真实 TLS/HTTP 服务，不依赖外部网站稳定性。实际免费源可另行小批量验证，但免费节点全失败也应如实呈现，不能填充示例成功。

## 验收

HTTP/HTTPS/SOCKS5 上游真实穿透、上游/目标 TLS 验证、错误凭据、目标 403/429、IPv4/IPv6、UDP 不支持、过短租约、队列/预算/并发、单个批量任务、重启恢复、身份变更和真实流量反馈均需覆盖。验证无用户 payload 重放、探测不驱动补池、待检测库存不重复购买、切页不丢后台任务、两端相同数据和凭据脱敏。Linux 用户态验证不能替代 T03/T15 的 eBPF。
