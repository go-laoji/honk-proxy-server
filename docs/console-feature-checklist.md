# honk-proxy-server 控制台功能清单

- 日期：2026-11-01（Asia/Shanghai）。
- 对应任务：[Issue #2](https://github.com/go-laoji/honk-proxy-server/issues/2)。
- 技术基准：[技术规划](technical-architecture-plan.md)、[整体规划](overall-plan-and-feasibility.md)。
- 状态：需求与验收清单，本文所有功能均为待实现项，不能据此判断已完成。
- 适用端：同一 React + Tailwind CSS MPA 在浏览器和 Desktop 共用；CLI 覆盖 P0 服务运维能力，桌面专属操作除外。

## 1. 优先级与通用验收

- **P0**：首个正式功能版本必需；Linux eBPF 相关 P0 是 Linux 发行门槛。
- **P1**：首版之后增强，按实际供应商、部署和运维需求推进。
- **P2**：后续储备，不纳入当前首版承诺。

本清单编号是后续 Issue 和验收记录的稳定引用，不是实施顺序；实施顺序以技术规划的 M0–M6 为准。

本版共 96 项：P0 75 项、P1 17 项、P2 4 项。P0 中的桌面或 Linux 专属操作按目标能力验收，不要求不适用的平台实现相同系统机制。

所有页面通用要求：共享布局和主题；真实 HTML 可直接访问与刷新；加载、空数据、断线、无权限、目标不支持、任务失败和版本冲突均有明确状态。筛选/分页写入 URL，长操作展示任务 ID 和最终结果，保存与实际激活分开显示，凭据不以明文出现在列表、日志或默认导出。

浏览器管理当前同源服务，Desktop 可切换本机/远端档案。页面必须展示当前服务身份；所有能力按目标服务返回结果判断，不能按客户端 OS 隐藏远端 Linux 能力。

## 19. 完成标准与需求追踪

每项功能从本文拆分到开发 Issue，保留功能编号；实现完成后记录 API/CLI 范围、页面入口、测试证据及已知限制。不要直接把文档中的 P0 标为完成，必须以可运行产物验收。

首个正式版本需同时满足：全部适用 P0、Linux 真正 eBPF、无桌面运行、独立 CLI 运维闭环、同一份 MPA 在浏览器与 Desktop 可用。原生专属能力使用相同页面上的能力适配，不为浏览器复制另一套业务页。

清单中 P1/P2 不应成为首版“顺手实现”的隐含范围；若新增必须项，需同步调整对应契约、阶段和验收。
