## 1. 优先级与通用验收

- **P0**：首个正式功能版本必需；Linux eBPF 相关 P0 是 Linux 发行门槛。
- **P1**：首版之后增强，按实际供应商、部署和运维需求推进。
- **P2**：后续储备，不纳入当前首版承诺。

本清单编号是后续 Issue 和验收记录的稳定引用，不是实施顺序；实施顺序以技术规划的 M0–M6 为准。

本版共 99 项：P0 80 项、P1 15 项、P2 4 项。P0 中的桌面或 Linux 专属操作按目标能力验收，不要求不适用的平台实现相同系统机制。

本次撤销原 AUTH-01、AUTH-02、AUTH-06 和 IN-02；原 AUTH-03/04/05 的连接功能分别迁为 INST-01/02/03，新增 INST-04 验收全功能直接访问。已撤销编号不复用，不将账号/权限功能放回后续储备。

所有页面通用要求：共享布局和主题；真实 HTML 可直接访问与刷新；加载、空数据、断线、目标不支持、任务失败和版本冲突均有明确状态，没有登录跳转或无权限页面。筛选/分页写入 URL，长操作展示任务 ID 和最终结果，保存与实际激活分开显示；上游凭据默认掩码、日志与默认导出脱敏，但不限制任何使用者操作相关功能。

浏览器管理当前同源服务，Desktop 可切换本机/远端档案。页面必须展示当前服务身份；所有能力按目标服务返回结果判断，不能按客户端 OS 隐藏远端 Linux 能力。

| PROV-02 | P0 | 提取 API 配置和凭据引用 | URL、参数、签名/鉴权、返回字段、协议/数量/地域、超时与抓取出口可配置，返回脱敏 |
| PROV-03 | P0 | 补充调度与限流退避 | 定时、低水位、到期预测、抖动、请求间隔与退避可见，每来源只有一个控制器 |
| PROV-04 | P0 | 手动提取与任务进度 | 展示提取参数和可能消耗的预算，返回任务 ID；重复点击合并，不重复购买 |
| PROV-05 | P0 | 同步结果与差异 | 展示新增/更新/移除/拒绝数量、有效期和实际发布版本 |
| PROV-06 | P0 | 同步失败保护 | 空结果、供应商鉴权失败和异常缩减不直接清空池；保留有效旧版本 |
| PROV-07 | P0 | 来源、批次与租约 | 可查租约 ID、批次、接收时间、有效期依据、剩余寿命与退休时刻；到期/撤销不选用 |
| PROV-08 | P0 | 供应商限额、白名单与鉴权诊断 | 请求/提取预算和限频可配置；有 API 时读取供应商额度/白名单，否则明确未知与手工前置条件 |
| PROV-09 | P0 | 库存水位与提前补池 | 最小/目标/最大库存、批量、提前窗口、最小寿命可配置；在途批次计入预算，空闲不无限提取 |
| PROV-10 | P0 | 有效期归一化与准入 | 校验绝对时间/TTL、单位、时区及起算点，寿命不足拒收；重启/时钟变化不延长租约 |
| PROV-11 | P0 | 增量批次与快照模式 | append_leases 保留仍有效旧批次，replace_snapshot 仅按全量契约删除缺失项 |
| PROV-12 | P0 | 提取幂等与结果不确定 | 请求/批次可追踪；无重复安全保证时不因超时自动重放消耗额度的 API，预算保守计算 |
| PROV-13 | P1 | 标准订阅扩展 | 按需求增加 URI/Clash 等来源；与短效租约模型隔离，不取代提取 API 主线 |

## 19. 完成标准与需求追踪

每项功能从本文拆分到开发 Issue，保留功能编号；实现完成后记录 API/CLI 范围、页面入口、测试证据及已知限制。不要直接把文档中的 P0 标为完成，必须以可运行产物验收。

首个正式版本需同时满足：全部适用 P0、Linux 真正 eBPF、无桌面运行、独立 CLI 运维闭环、同一份 MPA 在浏览器与 Desktop 可用。原生专属能力使用相同页面上的能力适配，不为浏览器复制另一套业务页。

直接访问专项验收：默认入口和全部 18 个 HTML 不跳转登录；不创建本项目账号/角色/登录会话/管理令牌；无凭据的读写 API、SSE、CLI 和代理连接均可工作。不将隐藏按钮、来源 ACL、只读角色或额外原生账号检查作为替代门禁；参数/版本校验、目标能力、上游认证与操作系统要求分别验收。

协议与供应商专项验收必须包括：浏览器 HTTP/HTTPS 目标、TLS 代理、SOCKS5 TCP；按用户提供的快代理官方短效提取 API 契约加云代理免费源实测，付费账号调用明确标为未验证且不要求采购；连续批次合并、近到期停止准入、提前补池、限频/预算、超时结果不确定、白名单失败和重启过期恢复。标准订阅和 SOCKS5 UDP 入站不作为替代该验收的演示路径。

清单中 P1/P2 不应成为首版“顺手实现”的隐含范围；若新增必须项，需同步调整对应契约、阶段和验收。
